## 写在最前面的一句

这个项目的技术难度不在存储，甚至不在检索——**在打标质量**。

向量检索、混合排序、pgvector 这些都是成熟方案，照着做就能跑通。真正决定「搜得准不准」的唯一变量是：**AI 有没有真的理解这张图想表达什么**。

模型改为用户可配置之后，这个判断没有变，但多了一层：**系统不再能假设模型的任何能力**。所有差异必须探测、所有输出必须校验、所有约束必须在界面上讲清楚。这就是为什么「测试连接」不是锦上添花，而是整个可配置设计的地基，见 [SPEC §9.7](../spec/09-decisions.md)。

**库改为共享之后，又多了一层：打标质量不再是私事。** 一个人配了烂视觉模型，污染的是所有人的搜索结果。这也是为什么视觉模型默认就用部署方配置、用户要改得先翻开「高级选项」，以及为什么管理员必须有「对任意图片重新打标」这个兜底。

注意力分配：

```
打标提示词与标签词表设计   ████████████  最重要
模型配置的探测与提示       ████████      可配置设计的地基
发送环节的体验            ██████        差异化所在
品牌视觉 / 界面样式       ████          门槛体验，随核心功能打磨
检索与排序                ███           成熟方案
存储与基础设施            █             不值得花时间
```

一句话：**这不是一个图片管理系统，是一个语义索引系统，图片只是它的载荷。**
