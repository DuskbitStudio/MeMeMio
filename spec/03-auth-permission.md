# §3 认证与权限

[返回索引](INDEX.md)

## §3.1 会话

邀请码注册。注册时消耗一个未使用且未过期的 `invite_codes` 记录，同一码不能重复使用。

会话使用 httpOnly + SameSite=Lax cookie，前后端同域，业务接口不使用 Authorization header，不需要 CSRF token 以外的跨域处理。生产环境设置 `Secure`，本地开发不设置。

**MCP 端点是唯一例外**（[§10.3](10-mcp.md#103-鉴权与访问令牌)）：它使用个人访问令牌（`Authorization: Bearer`），**只认令牌、不认 cookie**；反过来 `/api/v1` 的任何接口都不接受 Bearer。两种凭证不互通，不因为一次请求带了令牌就给它浏览器会话身份。

会话数据存 PostgreSQL，不引入 Redis——理由见 [§9.11](09-decisions.md)。

## §3.2 角色

两种角色，存在 `users.role`：

| 角色 | 说明 |
|---|---|
| `member` | 默认。可搜索全库、上传、编辑、删除自己上传的 |
| `admin` | 额外可配置 Embedding、重建索引、管理邀请码、删除和重打标任意图片 |

角色没有继承层级，只有这两级。首期不做工作区、分组或细粒度权限——一个圈子一个库，见 [§9.1](09-decisions.md)。

第一个注册的用户自动成为 `admin`。之后的角色变更只能由 `admin` 在管理页操作。

## §3.3 权限矩阵

| 操作 | 谁可以 |
|---|---|
| 搜索 / 浏览 / 使用 | 所有登录用户，**不做任何归属过滤** |
| 使用 MCP 只读工具 | 所有用户，以访问令牌鉴权；可读范围与「搜索 / 浏览 / 使用」一致，且**只读**，见 [§10.3](10-mcp.md#103-鉴权与访问令牌) |
| 上传 | 所有人，受存储配额限制 |
| 收藏 / 取消收藏 | 所有人，写自己的 `user_favorites` |
| 编辑描述与标签 | **所有人** |
| 删除（软删） | 上传者本人或 `admin` |
| 重新打标 | 上传者本人；`admin` 不限 |
| 配置视觉模型 | 所有人（改自己的） |
| 配置 Embedding / 重建索引 / 管理用户与邀请码 | 仅 `admin` |
| 配置运行参数（并发上限） | 仅 `admin`——它改的是全站资源分配与 AI 账单，不是谁的偏好（[§5.6](05-data-models.md)） |
| 人物改名、合并、移图、隐藏；系列新建、改名、改成员 | **所有人**，记操作人。**`proposed`**，见 [§6.7.1](06-endpoints.md) |
| 删除系列 | 创建者或 `admin`。**`proposed`**，同上 |
| 配置图片向量 / 补算人物向量 | 仅 `admin`——全站一份，花部署方的额度。**`proposed`**，见 [§6.7.5](06-endpoints.md) |

**编辑不设限、删除设限，是有意的不对称。** 标签在共享库里是公共品，谁发现标错了都顺手改掉对所有人都是净收益；删除是不可逆的破坏性操作。理由见 [§9.1](09-decisions.md)。

编辑必须记录 `edited_by` / `edited_at`，这是防滥用的唯一手段。首期不做完整修改历史表。

## §3.4 实施要求

> ⚠️ **风险的位置和隔离式多租户完全不同，不要照搬旧直觉。**
>
> 隔离库的头号风险在读路径——搜索接口漏一个归属条件就是全库泄露。**本项目没有这个风险**：全库可读就是设计本身。
>
> 风险整个挪到了**写路径**。删除接口漏一个归属检查，等于任何人都能删掉别人的贡献。

两条强制要求，必须在统一的数据访问层实施，不允许散落在各个 handler 里手写：

1. **所有 `memes` 写操作先过 `assertCanMutate(meme, actor, action)`。** `action` 区分 `edit`（全员）/ `delete`（上传者或 admin）/ `retag`（上传者或 admin）。函数内部判断，调用方不自行拼条件。
2. **所有 `memes` 读操作带 `deleted_at is null`。** 这是软删引入的新约束，漏掉的表现是「删掉的图又出现了」而不是报错，比漏归属检查更隐蔽。

例外只有一处：`admin` 的「已删除」管理视图显式查询软删记录，走独立的、名字带 `includeDeleted` 的方法，不复用常规查询。

## §3.5 密钥与响应

任何接口都不得返回完整 API Key，不论是用户自己的还是部署方默认的。

配置类接口返回的密钥字段固定为 `"****" + 后四位` 的形式，且是只读展示字段，客户端不能把它回传当作新值——回传该字符串视为「不修改」。

`CONFIG_ENC_KEY` 不出现在任何接口、任何日志、任何错误 `details` 里。

## §3.6 配额

每用户存储配额，按 `size_bytes` 累计，软删记录在保留期内仍计入配额（物理删除后释放）。

配额只限制磁盘占用，不限制图片数量——AI 成本由上传者自己的 key 承担，不需要用图片数量保护部署方的预算，见 [§9.3](09-decisions.md)。

超配额时上传接口返回 `QUOTA_EXCEEDED`，批量导入中途超限则剩余文件全部标记失败并在 `done` 事件里说明。
