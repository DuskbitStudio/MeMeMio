# 状态与导航

## 1. 能放 URL 的放 URL

搜索词、筛选条件、当前页签**全部放 query string**，不放组件 state。

```
/browse?q=今天真的不想上班
/browse?q=猫&emotions=无语&tags=猫&isAnimated=true&favorited=true
```

理由不是「优雅」，是这个产品的具体场景：**用户会把一次搜索的链接发给别人**（「你搜这个，第三张」）。放在 state 里就分享不了，刷新也丢。

> **搜索词的落点是 `/browse?q=`**（2026-09-26 首页改版前它是 `/?q=`）。老形式的链接
> 仍然认，首页会把它们重定向到新地址（SPEC §9.30）——**分享出去的链接已经散在外面了**，
> 这正是这条规则要保护的东西，它不能因为页面改版就变成 404。

参数名与[接口参数](../../../spec/06-endpoints.md)保持一致，不做第二套映射。**搜索词与筛选条件是同一串参数**，不分两套（见 §6）。

### 谁占一条历史记录

| 操作 | 写法 | 为什么 |
|---|---|---|
| 提交搜索词 | `push` | 一次搜索是可分享的状态，后退要能回到上一次搜索 |
| 改筛选条件 | `replace` | 筛选是「把这一屏看得更细」，不是一次跳转；每勾一个标签占一条历史，后退键就废了 |

这条 2026-09-26 立成规则：在此之前两端策略是**相反的**（浏览页四类写操作全 `replace`，搜索词 `push`），而合流之后两者落在同一个 URL 上，不写清楚就会各写各的。

**游标不进 URL**——它在内存里，页面地址不反映翻到第几屏。理由见 §6。

## 2. 服务端数据不复制到本地 state

结果列表、Meme 详情、配置——**这些的真相在服务端**，本地只缓存，不做第二份可编辑副本。

编辑标签后重新拉取或就地更新缓存，**不维护一个「本地已改但没提交」的影子对象**。那会在并发编辑时产生「我改的怎么没了」，而这个库是共享的，[所有人都能编辑](../../../spec/03-auth-permission.md)，并发编辑是常态不是边缘情况。

用 TanStack Query 一类的数据层，或者自己写一个薄缓存。**不要引入 Redux**——这个应用没有需要全局协调的复杂状态。

## 3. 真正的本地 state 只有四类

| 类 | 例 |
|---|---|
| 纯 UI | 弹窗开关、hover、输入框未提交的值 |
| 会话级 | 当前用户（从 `/auth/me` 来，登出清空） |
| 进行中的导入 | 批次 id + SSE 推来的进度 |
| 本机显示偏好（`localStorage`） | 浏览页图墙的密度档位（`features/browse/use-wall-density.ts`） |

第三类是唯一真正复杂的本地状态，见 [import-ux.md](import-ux.md)。

**什么能进 `localStorage`**：三条同时满足——**只影响本机显示、不影响结果集、丢了不心疼**。
影响结果集的（筛选、搜索词）进 URL（§1），别人点开分享链接要看到同一批图；显示偏好不进 URL，
别人点开也不该被改成你的密度。读时校验（不认识的值当没存过），读写都吞掉异常（隐私模式会抛），
退回默认值、不提示。

## 4. 路由

| 路由 | 说明 |
|---|---|
| `/` | 首页，**入口页**：搜索框只负责把人送到 `/browse?q=`，自己不搜、不渲染结果。主体是随机图墙 + 两条 rail + 待处理状态条（SPEC §9.30）。带 `?q=` 进来的一律重定向到 `/browse?q=` |
| `/browse` | 列表。**检索与筛选合一**：`?q=` 与七个词表维度同串（§6）。**全应用唯一的一条列表** |
| `/import` | 导入 |
| `/settings` | 设置。左侧分区导航、一次只显示一段，分区地址是 `#hash`（`#vision` / `#mcp` / `#invites` / `#embedding` / `#runtime` / `#retag` / `#users`，后五个仅管理员）；不带或不认识的 hash 落在 `#vision`。见 [settings-ux.md §2](settings-ux.md) |
| `/admin/*` | 旧地址，重定向到 `/settings` 的对应分区（`/admin/invites` → `#invites`，`users`、`embedding` 同理） |
| `/login` | 登录 / 注册 |

管理员分段对普通用户**不渲染**，**但那只是体验**——真正的权限在服务端。不要因为前端藏了入口就认为安全。

## 5. 登录回跳

`UNAUTHENTICATED` 跳登录页时**保留当前路由**，登录后跳回去。

用户从别人分享的搜索链接进来、发现没登录、登录完被丢到首页——搜索词就没了。这是最容易漏、也最容易被用户抱怨的一个细节。

## 6. 检索与筛选是**同一条**列表

**2026-09-26（裁定 1）起不再有「搜索页的列表」和「浏览页的列表」。** `q` 与七个词表维度是**同一串查询参数**，落在同一个端点上：先过滤后召回，翻页规则一致（[SPEC §6.3](../../../spec/06-endpoints.md)）。

| | 走哪个接口 | 翻页 |
|---|---|---|
| 列表（带不带 `q` 都是它） | `GET /memes` | 游标，无限滚动。**游标有两种含义**，按有没有 `q` 分派 |
| 首页图墙 | `GET /memes?random=true` | **不分页**，随机序没有下一页（§6.3.2） |
| 首页两条 rail | `GET /memes`（`favorited=true` / 默认序） | **不分页**，各取 8 张，其余走「查看全部 →」 |

本节此前的标题是「筛选与搜索是两条路径 / **不要把它们合成一个『万能搜索框』**」，2026-09-26 被裁定 1 取代。那条反对的是**同一个 URL 上两套游标语义、两个列表 hook 常驻一页**；合流做的是相反的事——一个端点、一套游标（含义按 `q` 分派）、一个列表 hook。

**同日稍晚（首页改版，SPEC §9.30）：那条残缺的第二条路彻底没了。** 首页曾自己渲染搜索结果、走冻结的 `GET /search`——不能筛、不能翻页，只是那条列表的一个更差的副本。现在首页**不渲染结果**：搜索框提交即 `navigate('/browse?q=…')`，带 `?q=` 进首页的老链接（分享出去的、书签里的）在 `App.tsx` 里 `<Navigate replace />` 到 `/browse?q=`。

仍然不能做的两件事：

- **首页不要再长出第二个列表。** 它上面三块内容（图墙、两条 rail）都是「取 N 张、不分页」，走 `lib/use-meme-batch.ts`；要翻页、要筛选一律去 `/browse`。首页自己渲染结果那条路**删过一次了**，别再修回来（为什么删：任务 2026-09-26-首页改版 §1）。
- **`q` 与 `random=true` 互斥**，两个都发会被拒。前端不要同时给出这两个入口（首页图墙不认 `q`，`/browse` 不认 `random`）。

### 落点：`/browse` 就是那条列表，搜索**横在两列上面、占满内容宽**

2026-09-26 实现落地，同日按产品负责人的意见改了两轮形状（第四稿定稿）。合一的列表就是 `/browse`，所以**搜索框必须在这一页上**——不然 `/browse?q=` 只能靠手打地址进，「检索与筛选同一条列表」在界面上就不成立。

- **在上面**：它是分栏组的**兄弟**（`browse.tsx` 外层那根纵向 flex：带 `shrink-0`、分栏组 `md:flex-1 md:min-h-0`），横跨两列、压在最上面。放进结果列的滚动区里最省事，代价是滚下去就没了；钉在结果列顶部能一直看得见，但只占右半边——产品负责人要的是**横着压在两根列上面**，一整条。**余量由 flex 分配**，`100svh − 顶栏` 那个算式不需要加搜索带这一项。
- **占满宽度**：整条 = 内容区整宽，**不封顶**。`max-w-2xl`（672px）那版同日被否——「搜索也要占满宽度」。
- **单行，输入在左、按钮在右**，与首页那支是同一个控件、同一个形状（`SearchBar` 不带分支）。第四稿初版在这一页做过**多行**（`multiline`），同日被否，分支连同它的两个坑一起删了：`Textarea` 没有 `forwardRef`（自动聚焦静默失效）、`TOUCH` 带着 `pointer-fine:min-h-8` 会把注册表的 `min-h-16` 压成一条。**要恢复先问**。
- **失焦也提交**（`submitOnBlur` 默认 `true`）：这一页输入完直接去点下面的结果是最常见的动作，不该要求先回车。
- **窄屏不钉**：手机上分栏组是普通块、滚的是整页，带跟着内容一起走（`md:flex-1` 只作用于 md 以上）。
- `autoFocus` 关掉：这一页是「翻着看」的，抢焦点会让手机上先弹键盘盖掉半屏。

> ⚠️ **2026-09-26 改口：失焦提交在两页上不再一样了。** 此前这条写的是「与首页逐字一致……
> 不要引入『这一页特意不提交』那类分支」，前提是**首页的搜索结果也在那一页上**。
> 首页改版把这个前提拿掉了（SPEC §9.30）——首页不渲染结果，输入框下面全是能点的东西
> （图、换一批、查看全部），**鼠标往下一按就触发 blur**，用户还没按回车就被送到 `/browse`。
> 所以首页显式传 `submitOnBlur={false}`，判据仍是「**这个页面进来是干嘛的**」
> （与同一个组件上的 `autoFocus` 同一条判据），不是「这一页想不一样」。
> 形状没变、控件没变，改的是一个 prop 的取值。

⚠️ 与聚焦环的关系：搜索带落在**没有 `overflow` 的外层容器**里，外壳 `p-6` 那 24px 就是环的余量，不需要再给谁补内边距。但**规则本身没废**：任何控件与 `overflow != visible` 的盒子之间至少留 4px，见 [styling.md](styling.md)「聚焦环要留出边距」。

写操作按 §1 那张表：**提交搜索词 `push`、改筛选 `replace`**，两者落在同一个 URL 上，所以分支要按「改的是 `q` 还是筛选」判，不能按页面判。**`q` 不算筛选项**：不进筛选角标、不该让「清除」按钮冒出来（清除清的是筛选，不是用户打的字），`clear()` 保留 `q`。

翻页的收工条件是 **`nextCursor === null`**，不是「这一页不满 `limit`」（[http.md §8](http.md)）——一页里若有条目在首发之后被软删，正常的页也会不满。

### 游标失效：丢弃、回第一页、说一句

解析失败、快照过期、**把检索游标接到无 `q` 的请求上**（或反过来），服务端一律返回 `VALIDATION_FAILED`，`details` 里没有额外信息——客户端要做的都是同一个动作，所以**前端也不区分这两种文案**（[SPEC §2.2](../../../spec/02-errors.md)）。

⚠️ **服务端不再静默返回第一页**（§1.3 的旧约定已取消）。所以「游标坏了」这件事**前端必须自己兜住**：在无限滚动里，静默回第一页等于把第一页往屏幕上又追加一遍，用户看到的是重复的图，而不是一个错误。

游标停在内存里、不进 URL（§1）：它是快照位置，不是人读的状态。要分享的是「搜什么、筛什么」。

## 7. `uploader` 和 `favorited` 是筛选项，不是安全边界

「只看我上传的」「只看我收藏的」是**可选筛选**，不传就是全库。这是[设计本身](../../../spec/00-overview.md)。

**不要默认帮用户加上 `uploader=me`。** 那会让共享库看起来像隔离库，用户会以为别人的图搜不到。

## 8. 乐观更新

收藏 / 取消收藏可以乐观更新——失败回滚，代价小。

**编辑标签和删除不要乐观更新。** 编辑要等服务端的词表校验结果；删除是破坏性操作，让用户看到它真的成功了。
