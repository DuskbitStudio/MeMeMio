# 已归档的跨端任务

[`joint-tasks/`](../../joint-tasks/README.md) 里验收通过的任务移到这里，**不删除**。

## 为什么留着

任务文件记的是**过程**：当时有哪几个选项、为什么选了这个、实测出来是什么结果。SPEC 只记**结论**。

结论会被后来的人质疑——"为什么不用 Redis"、"为什么 pHash 不做唯一约束"、"为什么词表里没有 XX"。SPEC §9 给的是一句话的理由，这里给的是当时的完整现场。

尤其是[供应商探测](../../joint-tasks/2026-09-13-provider-spikes.md)这类任务：它的结论会随供应商变化而失效，到时候需要知道**上次是怎么测的**才能重测。

## 归档时做什么

1. 确认结论已经搬进 [SPEC §9](../../spec/09-decisions.md)——**任务是过程，SPEC 是结论**，不要让别人靠读归档来了解现行契约
2. 状态改 `done`，补上验收日期和验收依据
3. 整份移过来，文件名不变
4. 从 `joint-tasks/README.md` 的当前任务表里移除

归档后不再修改。后续如果同一个主题有新结论，**新开一个任务，不要改旧的**。
