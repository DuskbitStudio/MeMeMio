# 设置页分区导航：左侧列分区，一次只显示一段

**状态**：`in_progress`——web 端已实现并回填 §8，待总管验收关闭。
**性质**：**web 单端**。不动 `api/`，不动 SPEC：[SPEC §9.9](../spec/09-decisions.md) 2026-09-24 那条措辞更正已经写明「哪些人看得见是契约，在哪个 URL 不是」，本任务只动后者。

## 1. 为什么要做

产品负责人 2026-10-25：「现在一长串，滚轮都累了。」

2026-09-25 走查量过管理员视角整页 **3262px**（[四页走查](../_archive/joint-tasks/2026-09-25-web-page-walkthrough.md)）。那之后又加了一整段 MCP 接入（令牌列表、内容范围、过滤器入口），现在是**一条滚动轴上叠七张卡**：视觉模型、MCP、邀请码、Embedding、运行参数、重建索引、重新打标、用户。重建索引 / 重新打标两张卡还没有 `id`，不进锚点目录。

**这是在推翻一个旧决定。** 三个管理页并进 `/settings` 时（[settings-merge](../_archive/joint-tasks/2026-09-18-settings-merge.md)「不做」一节）否决过页签，理由三条，逐条对一下：

| 当时的理由 | 现在 |
|---|---|
| 单页滚动 + 锚点已经够用 | 当时四段，现在七段，用户已经说不够用 |
| 页签要把状态放进 URL | 沿用 `#锚点` 当分区地址，状态本来就在 URL 里（§2） |
| 会打断重建进度轮询 | 切段不卸载，轮询照跑（§4.3） |

## 4. web 端要改什么

### 4.1 布局

- **md 以上**：左栏是分区导航，带「我的」「全站管理」两个组标题；右栏只显示当前段。左栏在滚动区里 sticky。原来那条「以下分段仅管理员可见」分隔线由组标题取代。
- **<768px**：分区导航换成段上方一行可横滑的标签条。sticky 与否执行者定，但不能挡住落点（`SettingsCard` 注释里 `scroll-mt` 分两档那条教训）。分栏断点按实测定，侧栏展开时 768–1024 宽度区间要看一眼挤不挤。
- 导航项保持**链接**（`<a href="#…">`），当前项标 `aria-current`。每一段是一个能复制、能直达的地址，不是页签控件里的一个状态。
- 页头那句说明保留，成员版本那句「其余设置由管理员维护」就是在解释为什么成员的设置页更短。

### 4.2 地址行为

- `/settings` 不带 hash → 显示第一段（视觉模型）。要不要 `replace` 成 `#vision` 由执行者定。
- 点导航项走链接的默认行为（写进历史），后退回到上一段。
- 成员带着管理员分区的 hash（如 `#users`），或者 hash 不认识 → 退回第一段，不报错，管理员分段照样不渲染。
- 段内的东西照常工作：`McpFilterSheet` 会 `scrollIntoView` 到 `#mcp-content-scope`，它在 MCP 段里，段可见时才会被调到。
- 切段后滚回内容区顶部。md 以上滚的是外壳那个 `ScrollArea`，手机上滚的是窗口（`SettingsCard` 注释里那两档）。
- `use-hash-scroll.ts`「盯着页面高度反复对齐」是为长页设计的：上面的段数据回来会把锚点往下推。一次一段之后大概率可以删掉或简化。判据是 `/admin/*` 三条重定向实测落点正确。

### 4.3 切段不能丢东西（最容易做错）

现在所有段同时挂载，下面三样都是靠这一点白捡的，改成一次一段后**一样都不能退化**：

1. 视觉「高级选项」里填了一半、还没测试，切去 MCP 再回来，填的东西还在；
2. 重建索引 / 重新打标的进度一直在轮询；
3. `RetagPanel` 的 `enqueuedCount` 基线（进度条的分母）只活在组件状态里（settings-ux.md §10），切走再回来进度条还在。

**推荐做法**：用户有权看的段全部挂载，非当前段加 `hidden`（它同时把内容移出 Tab 顺序和无障碍树，不要用透明度或移出视口来藏）。网络请求和现在一样——现在本来就是整页全量加载，不算新增负担。

如果执行者选择卸载非当前段，三样都要各自解决，并在验收里写清楚是怎么解决的。

⚠️ **两种「看不见」不要统一**：管理员分段对成员是**不渲染**（settings-ux.md §2 的硬话，那是权限分块），非当前段是 **`hidden`**（只是没轮到显示）。别因为引入了 `hidden` 机制，顺手把管理员分段也改成 `hidden`。

### 4.4 不动的

- `features/settings/settings-copy.ts` 的契约文案一个字不改。
- 视觉模型的「高级选项」折叠保留（settings-ux.md §3）。
- 各段内部结构不动。本次不做段内折叠或精简；某一段单独看仍然超过两屏的，记进验收，另开任务。

### 8.3 挂载还是卸载

**挂载，非当前段加 `hidden`**。三样东西都靠组件不卸载：视觉高级选项的未保存表单、两条轮询、`RetagPanel` 的 `enqueuedCount` 基线。卸载要各写一套外提状态，收益只有「少渲染几个 DOM」——而整页时代本来就是全量加载、请求数不变，所以没有换的必要。
管理员分段仍是 `isAdmin &&` 控制、**不渲染**，没有改成 `hidden`。

### 8.4 实现中发现的坑（值得记下）

1. **段上不能挂 `id`**。真跑出来：直达可滚动的 `#mcp` 时，浏览器在挂载后自己滚到那个 `section`，落点比内容区顶部低 104px（1264）/ 260px（390），而且发生在「回顶」之后。矮段没得滚，所以只在长段上露出来。改成地址只写 `data-section`、靠 `pickSection` 决定显示哪段后消失。
2. **CDP 里 `evaluate` 要带 `userGesture: true`**，否则 Chrome 的历史干预会跳过无手势的 `pushState`，后退测试退到 `about:blank`。
3. **同文档跳转**：`Page.navigate` 到同路径、只改 hash 不会重新加载，成员的 `/__fault` 因此不生效。验收脚本先跳 `about:blank` 再进。
